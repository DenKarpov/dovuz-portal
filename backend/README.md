# Бэкенд ДоВуз-Портала

Python 3.13 + FastAPI. Подход spec-first: источник правды — контракт
[`openapi/openapi.yaml`](openapi/openapi.yaml), слой API из него генерируется.
Контракт снят со слоя `frontend/src/app/api/` и повторяет его без изменений,
чтобы фронт заработал без переделки.

Сейчас готов контракт и сгенерированный слой; реализаций ручек ещё нет,
поэтому каждая отвечает 501.

## Как устроено

| Что | Где | Откуда |
|---|---|---|
| Контракт | `openapi/openapi.yaml` | пишется руками |
| Модели запросов и ответов | `app/generated/models.py` | datamodel-codegen |
| Роуты FastAPI и интерфейсы `<Тег>Api` | `app/generated/api/` | `codegen/generate.py` |
| Проверка куки сессии | `app/generated/security.py` | `codegen/generate.py` |
| Формат ошибок, CORS, сборка приложения | `app/errors.py`, `app/main.py` | пишется руками |

На каждый тег спеки генерируется абстрактный класс — например, `DirectionsApi`
с методом на каждую операцию. Роутер принимает запрос, проверяет его по спеке
и вызывает метод реализации. Реализация — обычный наследник; зависимости
из `__init__` FastAPI подставит сам:

```python
class DirectionsService(DirectionsApi):
    def __init__(self, db: DbSession) -> None:
        self.db = db

    def get_directions(self) -> list[DirectionResponse]: ...
```

Готовая реализация подключается в `app/main.py` вместо `not_implemented(DirectionsApi)`.
Если в ней не хватает метода, приложение не стартует.

Генератор свой, а не готовый: `fastapi-code-generator` теряет поля форм
в multipart-ручках, а `python-fastapi` из OpenAPI Generator объявляет поля форм
и query как `StrictInt` — строку `"5"` из формы такое поле не принимает.

## Запуск

```bash
uv sync
uv run uvicorn app.main:app --reload --port 8080
```

Swagger с контрактом — http://localhost:8080/docs. Без куки `dovuz_session`
ручки, которым по спеке нужна сессия, отвечают 401, остальные — 501.

## Как поменять контракт

1. Правим `openapi/openapi.yaml`.
2. `uv run python codegen/generate.py`
3. Дописываем реализацию новых методов.

Файлы в `app/generated/` руками не правятся: CI перегенерирует их и падает,
если результат разошёлся с закоммиченным.

## Проверки

```bash
uv run openapi-spec-validator openapi/openapi.yaml   # спека валидна
uv run python codegen/generate.py --check            # app/generated не отстал от спеки
uv run ruff check . && uv run ruff format --check .
uv run pytest
```

`tests/test_contract.py` — генеративная проверка на schemathesis: любой допустимый
по спеке запрос доходит ровно до своей операции, а недопустимое JSON-тело
отсекается с 400 раньше неё.

## Контракт: что нельзя нарушить

- **Именование.** Поля повторяют фронт как есть: в одних ответах snake_case (`first_name`),
  в других camelCase (`firstName`), query-параметры в camelCase. «Причесать» — сломать фронт.
- **401 и 403.** 401 — только «не вошёл»: на него фронт разлогинивает. «Вошёл, но нельзя» — 403.
- **Ошибки.** Всегда `{"message": "..."}`, фронт читает только это поле. Ошибки валидации —
  400 с русским текстом, а не 422.
- **Пагинация.** Параметры `pageNumber` (с нуля) и `pageSize`; ответ
  `{content, total_pages, total_size, page_number, page_size}`.
- **Роль.** Русская строка: «Администратор», «Модератор», «Пользователь» — по ней фронт
  считает права. У `GET /roles` поле `name` тоже русское: админка сравнивает с ним.
- **Сессия.** HTTP-only кука `dovuz_session`; фронт ходит с `withCredentials`, поэтому
  CORS отдаёт конкретный origin (`DOVUZ_CORS_ORIGINS`, по умолчанию `http://localhost:3000`).
- **Один path item на два смысла.** `GET /accounts/{account}` — никнейм, `DELETE /accounts/{account}` —
  id: для OpenAPI это один и тот же путь.

## Что нашлось во фронте

Контракт фронт не ломает, но эти места стоит поправить в нём самом:

- «Выйти» только чистит `sessionStorage`, кука остаётся действующей. В контракт
  добавлен `POST /auth/logout`, фронту нужно вызывать его в `logout`.
- Кнопку правки комментария фронт показывает по совпадению ника, то есть старый бэкенд
  отдавал ник автора анонимного комментария всем. По контракту его видят только сам автор
  и администратор, остальным приходит `null`.
- При создании ученика админка отправляет `class_name`, но `accountsApi.adminRegisterUser`
  это поле выбрасывает: класс до бэкенда не доходит.
- После смены никнейма фронт держит старый в `sessionStorage` и открывает профиль по старому
  адресу — до повторного входа видно «Пользователь не найден».
- Email чужого профиля фронт не показывает, поэтому по контракту он приходит только владельцу,
  модераторам и администратору.
